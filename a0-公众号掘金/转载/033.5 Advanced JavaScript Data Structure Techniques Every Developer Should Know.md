# 1. `Object.freeze()` vs `Object.seal()` – 锁定你的配置

# 🧠 问题：

在协作项目或大型应用中，共享配置对象可能会被意外修改，引入难以调试的副作用。当处理环境设置、Redux状态或模块之间共享的常量时，这尤其危险哦。

# 🚨 真实场景：

想象一个场景，开发者不小心修改了一个在多个服务中使用的配置对象。例如，`debug`标志可能在运行时被翻转，无意中禁用了生产环境中的日志记录。

```javascript
// 可变共享对象 — 危险
const config = { debug: true };
config.debug = false; // 允许这样做，可能导致隐藏的bug
```

# ✅ 解决方案：

使用`Object.freeze()`实现完全不可变性，或使用`Object.seal()`实现部分保护：

```javascript
// 完全不可变
const frozenConfig = Object.freeze({ debug: true });
frozenConfig.debug = false; // 静默失败（或在严格模式下抛出错误）
// 密封但值可变
const sealedConfig = Object.seal({ debug: true });
sealedConfig.newProp = 'x'; // 失败
sealedConfig.debug = false; // 有效
```

# ✅ 适用场景：

- 防止Redux/全局状态中的配置被意外更改
- 在前端和后端之间共享环境常量
- 保护库选项不被篡改

# 📈 影响：

有助于维护代码安全，强制执行数据契约，并消除由意外修改引起的bug。

# 2. `WeakMap`用于内存安全的DOM元数据存储

# 🧠 问题：

在动态UI繁重的应用程序中（如React、Angular甚至原生JS），如果使用标准Map将元数据与DOM元素关联，可能会导致**内存泄漏**。Map保留对键的强引用，即使元素从DOM中移除，也会阻止它们被垃圾回收。

# 🚨 真实场景：

你创建了一个工具提示库，使用`Map`跟踪悬停状态，但随着时间的推移，数千个已删除的DOM节点仍留在内存中。

```javascript
const metadata = new Map();
const button = document.getElementById('submit');
metadata.set(button, { clicked: true });
button.remove(); // 仍然保留在内存中！
```

# ✅ 解决方案：

改用`WeakMap`，它对键持有弱引用——允许垃圾回收清理未引用的对象：

```javascript
const weakMetadata = new WeakMap();
weakMetadata.set(button, { clicked: true });
button.remove(); // 有资格被GC回收 ✅
```

# ✅ 适用场景：

- 向DOM节点附加临时元数据（工具提示、事件监听器等）
- 在第三方库中存储特定于实例的元数据

# 📈 影响：

避免单页应用（SPA）和长期存在的UI中的内存泄漏。在组件库和自定义UI框架中特别有用哦。

# 3. `Array.from()`与映射函数 – 更干净地转换NodeList

# 🧠 问题：

当处理像`NodeList`这样的DOM集合时，大多数开发者会先将它们转换为数组，然后再映射它们——这个两步过程会影响可读性和性能呢。

```javascript
const divs = document.querySelectorAll('div');
const texts = [...divs].map(div => div.textContent); // 效率低下
```

# ✅ 解决方案：

使用带有映射函数的`Array.from()`在单个步骤中进行转换和迭代：

```javascript
const texts = Array.from(divs, div => div.textContent); // 高效
```

# 🚀 真实用例：

当抓取内容、构建虚拟DOM或预处理DOM节点进行渲染（如markdown渲染器）时，这个单行代码会让你的转换流程更干净哦。

# ✅ 适用场景：

- 转换和变换`NodeList`、`arguments`、`Set`或`Map`值
- 在富文本编辑器或可视化工具中解析或操作内容

# 📈 影响：

通过减少中间数组创建和方法链，提高性能和代码清晰度。

# 4. `Object.groupBy()`（第3阶段提案）– 无需Reduce地狱的原生分组

# 🧠 问题：

对数组数据进行分组是一项常见任务——无论是用户角色、销售报告还是API响应。大多数开发者使用冗长的`reduce()`逻辑或依赖Lodash等实用库。

```javascript
// 老式reduce方式
const grouped = users.reduce((acc, user) => {
  const dept = user.department;
  (acc[dept] ||= []).push(user);
  return acc;
}, {});
```

# ✅ 解决方案：

使用`Object.groupBy()`（目前处于第3阶段，但在Babel或带有polyfill的Node等现代环境中可用）：

```javascript
const grouped = Object.groupBy(users, user => user.department);
```

# 🧪 真实场景：

当你构建一个管理仪表板，需要按部门对员工进行分组或按地区聚合分析数据时——这让你可以清晰地表达逻辑，而无需自定义reduce逻辑。

# ✅ 适用场景：

- 按状态、类别、角色对API响应项进行分组
- 创建仪表板、摘要报告或分析图表

# 📈 影响：

降低复杂性，提高可读性，并减少对外部库的依赖。对于干净、声明式的代码来说是必备的哦。

# 5. `Set`和`Map`用于O(1)查找 – 停止使用数组进行成员检查

# 🧠 问题：

大多数初级和中级开发者使用数组来验证或跟踪数据——这导致每次查找的性能为**O(n)**，随着数据增长，代码会变慢。

```javascript
// 较慢：O(n)
const whitelist = ['admin', 'editor'];
if (whitelist.includes(userRole)) {
  grantAccess();
}
```

# ✅ 解决方案：

使用`Set`（或`Map`）进行常量时间**O(1)**查找：

```javascript
// 更快：O(1)
const whitelist = new Set(['admin', 'editor']);
if (whitelist.has(userRole)) {
  grantAccess();
}
```

# 🧪 真实示例：

用于登录系统、功能标志检查、数据去重、缓存API或验证用户输入。

# ✅ 适用场景：

- 检查项目是否存在于已知列表中（角色验证、标签过滤）
- 避免重复（Set）
- 将值与不仅仅是字符串的键关联（Map）

# 📈 影响：

显著提高性能，尤其是在处理大型数据集或频繁访问的列表时。
