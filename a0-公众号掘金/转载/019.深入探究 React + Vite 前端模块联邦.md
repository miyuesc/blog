# 什么是模块联邦（Module Federation）？

模块联邦是 **Webpack 5** 引入的一项黑科技，它能让 JavaScript 应用在**运行时动态加载**另一个应用的代码。简单说，就是不用在构建时把所有模块捆在一起，应用之间也能轻松共享代码。

你可以把它想象成“远程应用的懒加载”。它完美支持**微前端架构**，让应用的每个部分都能：

- 独立开发（各玩各的，互不打扰）
- 独立部署（改了就发，不用等别人）
- 无缝共享（代码复用，告别重复造轮子）

# 它能解决什么痛点？

在模块联邦出现之前：

- 前端巨石应用越做越大，慢得像蜗牛
- 应用间共享代码只能靠建库、维护库（版本冲突头都大了）
- 多个团队挤一个仓库，合并冲突家常便饭，部署排队等到花儿都谢了

有了模块联邦之后：

- 团队各自构建、测试、部署，爽歪歪
- 共享依赖只加载一次，省流量又提速
- 代码库想合就合，想拆就拆，渐进式改造无压力

# Vite 怎么玩转模块联邦？

Vite 不像 Webpack 那样原生支持模块联邦，但别慌！有个超赞的插件 `vite-plugin-federation`，让 Vite 应用也能拥有同款能力。

# 架构示意图

```
+--------------------+         +-------------------+         +-------------------+
  |    宿主应用        |  <--->  |  远程应用 A       |  <--->  |  远程应用 B       |
  | (仪表盘)           |         | (用户资料)        |         | (通知中心)        |
  +--------------------+         +-------------------+         +-------------------+
         |                                    |                             |
         |        运行时动态加载暴露的模块                                  |
         +-------------------------------------------------------------------+
```

每个应用都有自己的构建和部署流水线，但在运行时却能无缝协作，就像一个团队一样默契！

# Vite 实战案例

咱们来动手搞个 **宿主应用**（dashboard）和两个 **远程应用**（user-profile 和 notifications），看看它们怎么联邦起来！

# 1. 远程应用：`user-profile`（用户资料）

## 初始化项目

```
npm create vite@latest user-profile -- --template react
cd user-profile
npm install
npm install vite-plugin-federation  # 安装模块联邦插件
```

## vite.config.js

```javascript
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import federation from '@originjs/vite-plugin-federation';  // 引入模块联邦插件

export default defineConfig({
  plugins: [
    react(),
    federation({
      name: 'user_profile',  // 应用名称，随便起但要唯一
      filename: 'remoteEntry.js',  // 生成的远程入口文件名
      exposes: {
        './UserProfile': './src/UserProfile.jsx'  // 暴露出去的组件：键是别名，值是路径
      },
      shared: ['react', 'react-dom']  // 共享依赖，避免重复加载
    })
  ],
  build: {
    target: 'esnext',  // 支持现代浏览器特性
    minify: false,  // 开发环境先不压缩，方便调试
    cssCodeSplit: false  // CSS 不拆分，避免样式丢失
  }
});
```

## src/UserProfile.jsx

```jsx
export default function UserProfile() {
  return <div>👤 这是来自远程应用的用户资料组件</div>;  // 简单的组件内容
}
```

## 启动服务

```
npm run dev -- --port 5001  # 用 5001 端口启动，避免和其他应用冲突
```

# 2. 远程应用：`notifications`（通知中心）

## 初始化项目

```
npm create vite@latest notifications -- --template react
cd notifications
npm install
npm install vite-plugin-federation  # 老规矩，安装模块联邦插件
```

## vite.config.js

```javascript
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import federation from '@originjs/vite-plugin-federation';

export default defineConfig({
  plugins: [
    react(),
    federation({
      name: 'notifications',  // 这个应用叫 notifications
      filename: 'remoteEntry.js',  // 远程入口文件
      exposes: {
        './Notifications': './src/Notifications.jsx'  // 暴露通知组件
      },
      shared: ['react', 'react-dom']  // 和宿主共享 React 依赖
    })
  ],
  build: {
    target: 'esnext',
    minify: false,
    cssCodeSplit: false
  }
});
```

## src/Notifications.jsx

```jsx
export default function Notifications() {
  return <div>🔔 您有 3 条新通知！</div>;  // 带点 emoji 更生动
}
```

## 启动服务

```
npm run dev -- --port 5002  # 用 5002 端口，和其他应用区分开
```

# 3. 宿主应用：`dashboard`（仪表盘）

## 初始化项目

```
npm create vite@latest dashboard -- --template react
cd dashboard
npm install
npm install vite-plugin-federation  # 宿主也要安装插件哦
```

## vite.config.js

```javascript
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import federation from '@originjs/vite-plugin-federation';

export default defineConfig({
  plugins: [
    react(),
    federation({
      name: 'dashboard',  // 宿主应用名称
      remotes: {
        // 配置远程应用：键是别名，值是远程入口文件地址
        user_profile: 'http://localhost:5001/assets/remoteEntry.js',
        notifications: 'http://localhost:5002/assets/remoteEntry.js'
      },
      shared: ['react', 'react-dom']  // 和远程应用共享依赖
    })
  ],
  build: {
    target: 'esnext',
    minify: false,
    cssCodeSplit: false
  }
});
```

## src/App.jsx

```jsx
import { lazy, Suspense } from 'react';  // React 懒加载和加载状态组件

// 从远程应用加载组件（用上面配置的别名）
const UserProfile = lazy(() => import('user_profile/UserProfile'));
const Notifications = lazy(() => import('notifications/Notifications'));

function App() {
  return (
    <div>
      <h1>✨ 我的仪表盘</h1>
      {/* 用 Suspense 显示加载中状态 */}
      <Suspense fallback={<div>📦 加载用户资料中...</div>}>
        <UserProfile />
      </Suspense>
      <Suspense fallback={<div>📦 加载通知中...</div>}>
        <Notifications />
      </Suspense>
    </div>
  );
}
export default App;
```

## 启动服务

```
npm run dev -- --port 5000  # 宿主应用用 5000 端口
```

现在访问 `http://localhost:5000`，就能看到两个远程组件乖乖显示出来啦！是不是很神奇？

# 高级玩法

# 1. 共享依赖配置

不想同一个库被加载 N 次？这样配置：

```javascript
shared: {
  react: { singleton: true, requiredVersion: '^18.0.0' },  // React 必须是单例
  'react-dom': { singleton: true }  // ReactDOM 也一样
}
```

- **singleton: true**：确保整个应用只有一个库实例（避免 React 报“两个版本”的错）
- **requiredVersion**：指定版本范围，避免版本不兼容（比如 17.x 和 18.x 混用）

# 2. 动态远程应用地址

有时候远程应用地址是从接口或配置文件拿的，这时候可以动态配置：

```javascript
remotes: {
  notifications: () => Promise.resolve(window.remoteNotificationUrl)  // 从全局变量获取地址
}
```

然后在 HTML 或运行时配置里注入这个 `window.remoteNotificationUrl` 就行啦，灵活度拉满！

# 3. 带错误边界的懒加载

远程组件加载失败了怎么办？加个错误边界优雅处理：

```jsx
import { lazy, Suspense } from 'react';

const RemoteComponent = lazy(() => import('remote_app/Component'));

// 错误边界组件：捕获子组件错误
function ErrorBoundary({ children }) {
  try {
    return children;
  } catch (err) {
    return <div>⚠️ 模块加载失败，请稍后再试~</div>;  // 用户友好的提示
  }
}

function App() {
  return (
    <ErrorBoundary>
      <Suspense fallback={<div>加载中...</div>}>
        <RemoteComponent />
      </Suspense>
    </ErrorBoundary>
  );
}
```

# 4. 暴露多个模块

一个远程应用可以暴露多个组件，宿主想用哪个就引哪个：

```javascript
exposes: {
  './ComponentA': './src/ComponentA.jsx',  // 暴露组件 A
  './ComponentB': './src/ComponentB.jsx'   // 暴露组件 B
}
```

宿主按需导入，不浪费一丝资源~

# 5. 宿主和远程应用的版本冲突处理

共享依赖时，可以控制宿主接受什么版本的依赖：

```javascript
shared: {
  react: {
    singleton: true,          // 单例模式
    strictVersion: true,      // 严格版本检查
    requiredVersion: '^18.2.0',  // 只接受 18.2.x 版本
  },
}
```

- **strictVersion: true**：版本不匹配时，远程应用就不加载了（避免运行时爆炸）
- 构建大型分布式系统时，记得做好版本协商或降级 fallback 机制哦！

# 6. 离线或加载失败时的降级方案

远程应用可能会挂掉（比如正在部署），这时候降级方案就派上用场了：

```jsx
const Notifications = lazy(() =>
  import('notifications/Notifications')
    .catch(() => import('./local/NotificationsFallback'))  // 加载失败就用本地 fallback
);
```

用户体验直接拉满，再也不怕服务抖动啦！

# 7. 跨框架联邦

不同框架也能联邦哦！比如 React 宿主 + Vue 远程应用：

- 写个包装器（wrapper）在 React 里挂载/卸载 Vue 组件
- 推荐远程应用暴露原生 Web Components（兼容性更好）

前端框架混战？模块联邦表示：我全都要！

# 8. 联邦应用的样式隔离

多个联邦应用可能会样式冲突（类名重复），解决方案：

- 用 **CSS Modules**、**Scoped SCSS** 或 **Shadow DOM**（样式隔离神器）
- 每个远程应用的类名加个独特前缀（比如 `user-profile-xxx`）

样式打架？不存在的！

# 9. 联邦路由

如果每个远程应用都有自己的路由，可以在宿主搞个中央路由：

```jsx
<Route path="/user" element={<UserProfile />} />  // 用户资料路由
<Route path="/notifications" element={<Notifications />} />  // 通知路由
```

也可以让远程应用自己导出路由配置，然后动态挂载到中央路由里，灵活得很！

# 10. 联邦状态共享（高级）

状态共享容易导致紧耦合，尽量避免！但如果实在需要，可以试试：

- 通过模块联邦暴露一个共享的 Redux Store
- 把 Context API 设为单例共享
- 发布订阅模式（比如 eventemitter3，或浏览器原生的 CustomEvent）

记住：状态共享需谨慎，解耦才是王道！

# 部署最佳实践

- 每个应用部署在独立的子域名或端口（避免跨域问题）
- `remoteEntry.js` 文件名加哈希（比如 `remoteEntry.[hash].js`），防止缓存坑
- 用环境变量或配置中心注入远程应用地址（改地址不用重新构建）
- 给宿主和远程应用之间加个契约测试（API 变了自动报警）

部署稳如老狗，运维小哥笑开花！

# 什么时候该用模块联邦？

**超适合这些场景：**

- 企业级大型应用（人多项目大，拆就对了）
- 多个团队并行开发（各干各的，互不耽误）
- 需要运行时插件化的应用（像 VS Code 插件那样动态扩展）

**这些情况就别用了：**

- 小/中型应用，就一个团队开发（杀鸡焉用牛刀）
- 部署复杂度比带来的好处还大（折腾半天不值当）
