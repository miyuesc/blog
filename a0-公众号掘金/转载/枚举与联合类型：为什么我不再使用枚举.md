# 枚举与联合类型：为什么我不再使用枚举

> 原文：[《Enums vs Union Types: Why I Stopped Using Enums Everywhere》](https://medium.com/@ie33/enums-vs-union-types-why-i-stopped-using-enums-everywhere-30b3c5ea5af8)
>
> 作者：[IE 33](https://medium.com/@ie33)



我以前在用 TypeScript 的时候，默认就爱用枚举（Enums）。讲真，它看起来简直是定义一组命名值的完美方式，无可挑剔。



直到有一天，一位同事在代码审查时给我留下了这么一条评论：

> “你为啥不用联合类型（Union Type）呢？那玩意儿更好，性能也更炸裂。”

好家伙，就这一句话，直接给我问懵了，让我陷入了沉思：**难道我一直以来都用错枚举了？**

于是，我决定深入研究一下，把这两种方法扒个底朝天，然后把我的发现分享给你们。

### 枚举（Enums）到底有啥毛病？

咱先来看个例子：

```typescript
Copyenum BoxType {
  PRIMARY = "primary",
  INFO = "info",
  ERROR = "error"
}

const alertBoxType: BoxType = BoxType.PRIMARY;
console.log(alertBoxType); // "primary"
```

你看，枚举这东西，写出来**看起来干净又整洁**，相当有条理。

但是，咱们再看看它编译后生成的 JavaScript 代码是啥样的：（我用了这个[在线工具](https://transform.tools/typescript-to-javascript)）

```javascript
Copyvar BoxType;

(function(BoxType) {
  BoxType["PRIMARY"] = "primary"
  BoxType["INFO"] = "info"
  BoxType["ERROR"] = "error"
})(BoxType || (BoxType = {}))

const alertBoxType = BoxType.PRIMARY
console.log(alertBoxType) // "primary"
```

当 TypeScript 编译这个枚举时，它居然变成了一个 JavaScript **对象！**

等会儿……啥玩意儿？！我一直以为枚举只是个类型而已，闹了半天，它居然还创建了额外的运行时对象。

所以，**这玩意儿的问题就来了：**

- **多余的 JavaScript 代码 =>** 打包体积更大了。
- **性能更慢** **=>** 需要进行对象查找。

### 更好的替代方案 → 联合类型（Union Types）：

相比之下，联合类型就牛逼了，它在**运行时根本不存在**。它们纯粹是 **TypeScript 的语法结构**，这意味着它们在**编译后就消失得无影无踪**了。

咱们用联合类型重写一下刚才的例子：

```typescript
Copytype BoxType = "primary" | "info" | "error";

const alertBoxType: BoxType = "primary";
console.log(alertBoxType); // "primary"
```

当 TypeScript 编译这段代码时，输出的代码那叫一个干净，你瞅瞅：

```javascript
Copy"use strict";
const alertBoxType = "primary"
console.log(alertBoxType) // "primary"
```

**发现了没，变化在哪？**

+ **联合类型在编译时完全消失 =>** 打包体积更小。
+ **直接进行字符串比较 =>** 性能更好。

不过话说回来，有时候用枚举还是很有必要的。

### 啥时候必须得用枚举呢？

- 枚举的一大杀手锏就是**反向查找**——意思就是，你可以通过值（value）来找到对应的键（key）。

举个栗子：

```typescript
Copyenum HttpStatus {
  OK = 200,
  NOT_FOUND = 404,
  INTERNAL_SERVER = 500,
}

console.log(HttpStatus.OK); // 200
console.log(HttpStatus[200]); // "OK"
```

`HttpStatus[200]` 会返回 `"OK"`——这波操作，联合类型可就望尘莫及了。

- 枚举的另一个优点是：**使用数字枚举来保持清晰的映射关系**，咱们再看个例子就明白了：

```typescript
Copyenum UserRole {
  Admin = 1,
  Editor = 2,
  Viewer = 3,
}

const getUserRole = (roleId: number): string => {
  return UserRole[roleId] || "Unknown";
};

console.log(getUserRole(1)); // "Admin"
console.log(getUserRole(4)); // "Unknown" (not in Enum)
```

正如你在上面例子中看到的，枚举可以轻松地将 **ID 映射为可读的名称**。

### 总结一下：

我现在遵循一个简单的原则：

\- 大多数情况下，我都用**联合类型**。
- 只有当**枚举**能带来实实在在的好处时（比如反向查找或映射数值），我才会用它。

下次再有人问你 *“你为啥不用联合类型呢？”* 的时候，你就知道该怎么回答了，嘿嘿 =D
